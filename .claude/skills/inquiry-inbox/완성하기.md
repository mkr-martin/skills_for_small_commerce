# 답변 보내기 — 직접 완성하기

이 스킬은 문의를 **모으기만** 합니다. 그런데 **답변 보내기도 API 로 할 수 있습니다** — 세 채널 모두 공식 문서에 "답변 등록" API 가 있습니다.
코드를 넣지 않은 이유: 한 번 나가면 고객이 바로 보고, 채널에 따라 **취소·수정이 안 되며**, 가게마다 받는 문의 종류와 권한이 달라 "모두에게 맞는 한 벌"이 없기 때문입니다.

이 문서는 사장님이 클로드와 **대화로** 자기 가게에 맞는 보내기를 만들 때 쓰는 재료입니다. 순서: ① 아래 **핵심 질문 6개**에 답한다 → ② **재료** 표에서 필요한 줄만 고른다 → ③ **안전장치**를 빼지 않고 만든다 → ④ 연습 모드로 끝까지 돌려 본 뒤 실제로.

## 1. 핵심 질문 6개 — 코드보다 먼저

### (1) 우리 가게에 오는 문의는 어떤 종류인가?
채널마다 문의가 들어오는 문이 여러 개고, API 도 문마다 따로입니다.

| 채널 | 문의 종류 | 모으기(이 스킬) | 답변 API |
|---|---|---|---|
| 네이버 | 고객 문의(주문 관련) | ✅ | 있음 — 등록·수정 |
| 네이버 | 상품 문의(상품 페이지 Q&A) | ✅ | 있음 — 등록·수정 겸용 |
| 쿠팡 | 상품별 고객문의 | ✅ | 있음 — 등록만 |
| 쿠팡 | 쿠팡 고객센터 문의(상담사가 넘긴 건) | ✅ (답변 필요한 것만) | 있음 — 등록만 · 24시간 안 |
| 카페24 | 게시판 글(상품 Q&A · 1:1 등) | ✅ (고른 게시판) | 댓글 등록·삭제 / 답변글 등록 |

> 클로드에게 이렇게 물어보세요: **"지난 2주 문의함.csv 를 채널·종류별로 세어 줘. 어느 종류부터 보내기를 만들면 좋을까?"**

### (2) 얼마나 거슬러 올라가 가져오나?
기간·페이지 한도·호출 제한이 채널마다 다릅니다. 보내기 전에 최신 상태를 한 번 더 읽어 "이미 답이 달렸는지" 확인하는 것이 안전합니다.
- 네이버 고객 문의: 최대 365일 · 페이지당 10~200건 · 상품 문의: 페이지당 최대 100건
- 쿠팡: 두 조회 API 모두 **한 번에 7일까지** · 페이지 크기 최대 50(상품별) / 30(고객센터) · 초당 5회
- 카페24: 한 번에 1년 미만 · 한 번에 100건 · offset 최대 8000 · 호출건수 제한 40

> 클로드에게 이렇게 물어보세요: **"보내기 직전에 그 문의가 아직 미답변인지 다시 확인하는 단계를 넣으려면 어느 API 를 다시 불러야 해?"**

### (3) 답변 등록 API — 새로 쓰기만 되나, 수정도 되나? 글자 수 제한은? 보내면 취소되나?
아래 **2. 재료** 표가 답입니다. 요약:
- 네이버: 고객 문의는 등록·수정 따로, 상품 문의는 같은 API 로 등록·수정. 삭제 API 는 이 문서 묶음에서 확인 안 함(**미확인**). 글자 수 제한은 문서에 없음(**미확인**).
- 쿠팡: **등록만.** 같은 문의에 두 번 보내면 오류. 고객센터 답변은 2~1,000자. 수정·삭제 API 는 CS 문서 7개에 없음 → **보내면 API 로 되돌릴 수 없음**(윙 화면에서 처리).
- 카페24: 댓글 등록·**삭제 둘 다 있음**. 글자 수: 작성자명 100자 · 댓글 비밀번호 1~20자, 본문 제한은 **미확인**.

> 클로드에게 이렇게 물어보세요: **"쿠팡 고객센터 문의에 답을 보냈는데 오타가 있으면 어떻게 고쳐? 문서 근거로 답해 줘."**

### (4) 키 권한은 어디까지 줄까?
**읽기만 되는 키로 시작하고, 보내기 권한은 나중에** 따로 켭니다.
- 카페24: 지금 로그인 권한은 읽기 둘뿐입니다 — `mall.read_community`(게시판 읽기 · 이 스킬) · `mall.read_product`(상품 읽기 · 매대 점검). 보내기를 만들 때 `shared/channels/cafe24.py` 의 `SCOPES` 에 `mall.write_community` 를 더하고 **로그인을 한 번 다시**(`python3 shared/channels/cafe24.py login`) 합니다.
- 네이버: 커머스API센터 애플리케이션의 API 권한에서 문의 "답변" 권한을 따로 확인합니다(화면 구성은 **미확인**).
- 쿠팡: OPEN API 키는 읽기·쓰기를 나누지 않습니다(**추측** — 문서에서 권한 구분을 찾지 못함). 그래서 쿠팡은 코드 쪽 안전장치가 더 중요합니다.

> 클로드에게 이렇게 물어보세요: **"카페24 보내기 권한을 켜려면 내가 직접 할 일만 순서대로 알려 줘."**

### (5) 누가 최종 승인하나?
보내기 버튼은 **사람만** 누릅니다. 아래 3절의 "두 번 확인"은 바꾸지 않습니다 — 빠르게 하려고 확인을 줄이거나, 보내기 명령을 클로드 코드 허용 목록에 넣으면 클로드가 혼자 보낼 수 있게 됩니다.
직원이 여럿이면 "답은 누가 쓰고, 보내기 '예'는 누가 하나"를 정해 둡니다.

> 클로드에게 이렇게 물어보세요: **"보내기 명령이 허용 목록에 들어가 있지 않은지 .claude/settings 를 확인해 줘."**

### (6) 실패하면 어떻게 다시 보내나?
- 실패한 건은 상태를 바꾸지 않고 `오류` 칸에 이유를 남겨, 고친 뒤 **미리보기부터 다시** 합니다.
- 보낸 건은 별도 기록 파일에 한 줄씩 덧붙여 **같은 문의에 두 번 보내지 않게** 막습니다(엑셀로 표를 덮어써 상태가 되돌아가도 기록이 막아 줌).
- 쿠팡 고객센터 문의는 24시간이 지나면 쿠팡이 자동 종결해 API 로 답할 수 없습니다 → 윙 화면에서.

> 클로드에게 이렇게 물어보세요: **"보내다가 3건 중 2번째에서 인터넷이 끊기면 표와 기록이 어떤 상태로 남는지 설명해 줘."**

## 2. 재료 — 채널별 답변 API (공식 문서로 확인한 것만)

문의함.csv 의 `id` 에 답변에 필요한 번호가 이미 들어 있습니다: `채널:종류:번호[:보조번호]`.
인증·요청은 `shared/channels/` 의 `request(method, path, params, body)` 를 그대로 쓰면 됩니다(서명·토큰 처리 포함).

### 네이버 커머스 API (커머스API센터 문서 · 문서 번호는 원천 정리본 기준)
| 할 일 | 메서드 · 경로(`/external` 뒤) | 본문 | 근거 |
|---|---|---|---|
| 고객 문의 답변 등록 | `POST /v1/pay-merchant/inquiries/{inquiryNo}/answer` | `answerComment`(필수) · `answerTemplateId`(선택) | 033 |
| 고객 문의 답변 수정 | `PUT /v1/pay-merchant/inquiries/{inquiryNo}/answer/{answerContentId}` | 위와 같음 | 034 |
| 상품 문의 답변 등록/수정 | `PUT /v1/contents/qnas/{questionId}` | `commentContent`(필수) | 042 |
| 상품 문의 답변 템플릿 목록 | `GET /v1/contents/qnas/templates` | — (응답 필드 **미확인**) | 041 |

- id: `naver:inquiry:<inquiryNo>` · `naver:qna:<questionId>`. 수정에 쓰는 `answerContentId` 는 고객 문의 조회 응답(037)에 있습니다.
- ⚠️ 조회는 `/v1/pay-user/…`, 답변은 `/v1/pay-merchant/…` — 문서 그대로이나 실계정에서 한 번 확인 필요(**미확인**).
- 삭제 API · 글자 수 제한: **미확인**.

### 쿠팡 윙 OPEN API (CS APIs)
| 할 일 | 메서드 · 경로 | 본문(전부 필수) | 근거 |
|---|---|---|---|
| 상품별 고객문의 답변 | `POST /v2/providers/openapi/apis/api/v4/vendors/{vendorId}/onlineInquiries/{inquiryId}/replies` | `content` · `vendorId` · `replyBy`(윙 로그인 아이디) | 360033645174 |
| 고객센터 문의 답변 | `POST /v2/providers/openapi/apis/api/v4/vendors/{vendorId}/callCenterInquiries/{inquiryId}/replies` | `vendorId` · `inquiryId` · `content`(2~1,000자) · `replyBy` · `parentAnswerId`(숫자) | 360034156233 |
| 고객센터 문의 확인(답변 불필요 건) | `POST …/callCenterInquiries/{inquiryId}/confirms` | `confirmBy` | 360034204013 |

- id: `coupang:online:<inquiryId>` · `coupang:cs:<inquiryId>:<parentAnswerId>`(이관글 번호까지 담아 둠).
- 줄바꿈은 `\n`. 같은 문의에 두 번 보내면 "동일한 답변이 존재합니다" 오류. 삭제된 상품문의엔 답 불가.
- 고객센터 답변은 미답변(`inquiryStatus: progress` · `partnerTransferStatus: requestAnswer`)일 때만, 24시간 넘으면 자동 종결.
- 응답 본문 `code` 가 `"200"` 이 아니면 실패로 봅니다. 수정·삭제 API 없음(CS 문서 7개 기준).
- `replyBy` 용 키(예: `COUPANG_WING_USER_ID`)를 `.env` 와 `.env.example` 에 새로 만들어야 합니다.

### 카페24 Admin API (05 Community)
| 할 일 | 메서드 · 경로(`/api/v2/admin` 뒤) | 본문 | 근거 |
|---|---|---|---|
| 게시글에 댓글 등록 | `POST /boards/{board_no}/articles/{article_no}/comments` | `{"shop_no":1, "request":{…}}` — `content` · `writer`(100자) · `password`(1~20자) 필수 · `secret`(T/F) 등 선택 | Boards articles comments |
| 댓글 삭제 | `DELETE /boards/{board_no}/articles/{article_no}/comments/{comment_no}` | — | 같은 절 |
| 답변 게시글 등록(1:1 게시판식) | `POST /boards/{board_no}/articles` + `reply_article_no` | `writer` · `title`(256자) · `content` · `client_ip` 필수 | Boards articles |

- id: `cafe24:<board_no>:<article_no>`. 권한 `mall.write_community` · 호출건수 제한 40 · 댓글은 1회 1건.
- `{"shop_no":1, "request":{…}}` 감싸기는 카페24 문서 공통 등록 예시 모양입니다. 댓글 API 의 응답 예시는 문서 정리본에 비어 있음(**미확인**).
- 댓글로 답할지 답변글로 답할지는 게시판 설정(`reply_feature`·`use_comment`)에 따라 고릅니다. 비밀글 문의에 공개 댓글을 달지 않도록 `secret` 을 확인하세요.
- 작성자명·비밀번호용 키(예: `CAFE24_REPLY_WRITER` · `CAFE24_REPLY_PASSWORD`)를 새로 만들어야 합니다.

## 3. 안전하게 만드는 법 — "두 번 확인" 설계 (글로만 · 이대로 만드세요)

목표: **사장님이 눈으로 본 그 내용만, 사장님이 두 번 '예' 한 뒤에만, 한 번만** 나간다.

1. **표에서 고르기** — 문의함.csv 에 `보낼준비` 같은 상태 값과 `보낸시각` · `오류` 열을 더합니다. 사장님이 답을 쓰고 상태를 `보낼준비` 로 바꾼 줄만 대상입니다. 답이 빈 줄은 뺍니다.
2. **미리보기** (`send.py preview`) — 보낼 건 **전부**를 채널 · 문의 원문 · 답변 전문 그대로 화면에 찍습니다. 요약하지 않습니다.
3. **확인 토큰** — 미리보기가 짧은 무작위 토큰을 만들고, 숨김 파일(예: `output/문의/.send_token`)에 **보낼 목록 전체의 해시(id·원문·답변)** 와 **만료 시각(10분)** 을 적습니다. 토큰은 **한 번 쓰면 지웁니다.**
4. **1차 확인(대화)** — 클로드가 미리보기 출력을 사장님께 **그대로** 보여 주고 "보낼까요?" 묻습니다. 사장님이 "예" 해야 다음으로.
5. **2차 확인(권한창)** — 보내기 명령은 `send.py confirm <토큰> --yes-send` 처럼 **확인어가 붙어야만** 움직이고, 이 명령은 **클로드 코드 허용 목록에 넣지 않습니다.** 그래서 실행할 때마다 클로드 코드 권한창이 한 번 더 묻습니다. SKILL.md 맨 위에 "사장님 확인 없이 confirm 을 실행하지 말 것 · 허용 목록에 넣지 말 것"을 적습니다.
6. **거부 조건** — confirm 은 다음이면 아무것도 보내지 않습니다: 토큰 다름 · 10분 지남 · 미리보기 뒤 표 내용이 바뀜(해시 다름) · 확인어 없음.
7. **한 건마다 저장** — 한 건 보낼 때마다 표를 저장합니다(성공 = 상태 `보냄` + 보낸시각 / 실패 = 상태 그대로 + `오류`). 중간에 끊겨도 보낸 건은 `보냄` 으로 남습니다. 표는 임시 파일에 쓰고 바꿔치기해 반쪽짜리 표가 생기지 않게.
8. **보낸 기록** — `output/문의/보낸기록.csv` 같은 파일에 보낸 id 를 **덧붙이기만** 하고, 미리보기에서 이미 기록된 id 는 뺍니다(엑셀로 표를 덮어써도 두 번 안 나감).
9. **연습 모드** — `--dry-run` 이면 API 를 부르지 않고 '보냈다고 치기'만 합니다. 연습용 표로 만료·내용 변경 거부까지 **끝까지 돌려 본 뒤** 실제로 씁니다. 연습 토큰으로 실제 발송은 안 되게(토큰에 연습 여부도 기록).
10. **되돌리기** — 채널마다 다릅니다: 카페24 댓글은 삭제 API 로 지울 수 있고, 네이버는 수정 API 로 고칠 수 있고, 쿠팡은 API 로 되돌릴 수 없습니다. 그래서 쿠팡은 특히 미리보기를 꼼꼼히.

> 클로드에게 이렇게 물어보세요: **"완성하기.md 3절 설계대로 네이버 상품 문의 하나만 보내는 send.py 를 만들어 줘. 먼저 연습 모드로만 돌려 보자."**
